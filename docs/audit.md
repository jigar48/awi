# Pre-release audit — AWI V1

Date: October 19, 2026. Baseline: commit `9bc61c1`, branch `codex/awi-v1`. This audit inspected the implementation, original supplied brief, all original 37 tests, documentation, packaged artifacts and CI configuration. The brief ends mid-sentence in report redaction; no absent requirements are claimed. Changes fix V1 defects and release verification gaps; no new product features or remote actions were introduced.

## Recommendation

**NO-GO for publishing until the complete hosted CI matrix passes, especially macOS.** The exercised final implementation has no known remaining critical/high defect from this audit, but local Windows and WSL evidence does not prove every advertised platform/runtime combination. Complete the configured nine Windows/macOS/Linux × Node 22/24/26 jobs before publishing. Publication also requires the maintainer's explicit authorization; none was performed here.

## Rule completeness review

| Rule   | Audit conclusion after fixes                                                                                                                                                                                                                                                                                    |
| ------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| AWI001 | Fingerprints preserve object key order normalization, array order, types, Unicode code points, null vs absent and explicit ignored paths. Threshold 4, disjoint 100-call windows, same trace/parent, reliable sequential evidence. Intentional polling remains a documented false positive.                     |
| AWI002 | Default 3; requires explicit error status and matching nonblank recorded error information. Matching hashes are internal only; more specific findings suppress AWI001 for their exact covered operations. Unknown status and differing outcomes do not qualify.                                                 |
| AWI003 | Exact contiguous bounded cycles; default 3 repeats, maximum default length 6/configuration cap 16; shortest matching period wins and consumed sequences are not rescanned. Single-call repetition is excluded. Concurrent/missing evidence cannot establish a cycle.                                            |
| AWI004 | Default 5 attempts/30 seconds; preceding attempts must explicitly fail. A terminal success/unknown stops the chain; later calls cannot erase an earlier match. Exact time boundaries; absent timing excludes sequences. Retry intent remains inferred and may coexist with AWI002 for distinct timing evidence. |
| AWI005 | Separately counts all operations and observed parent depth (roots=1). Thresholds are policy, not proof of bugs. Missing parents warn and give lower bounds; duplicate IDs, parent cycles and reversed endpoints fail explicitly.                                                                                |
| AWI006 | Associates only directly implicated leaf operations with recorded usage/cost, unions related IDs once, keeps input/output/total independent and currencies separate. Missing values remain absent; parent totals and unrelated model usage are not attributed. Empty usage does not fabricate a finding.        |

Cycle scan lengths and repeat thresholds are capped; failed candidate scans have a bounded repeat count before the configured minimum would qualify and consume the sequence. No combinatorial subsequence search is present. The existing 50,000-operation regression guard remains; tests did not relax detector performance assertions. Findings cap at 1,000 with complete:false and exit 1. Content budgets fail explicitly rather than returning a falsely clean partial analysis.

## Ingestion, interfaces and reporting

Canonical v1 trace/collection input is strict, supports nested operations/handoffs via parent structure and metadata, preserves generic spans and optional resource evidence, and groups by trace identity across files. The OTLP adapter supports only the documented protobuf JSON subset. Format ambiguity and malformed required fields fail; missing/unknown evidence is not invented. Unsupported AnyValue encodings are omitted from interpretation; this is not universal exporter compatibility.

All required commands/options, ESM public imports, configuration defaults/rejections and exit codes were exercised. Exit 1 takes precedence over severity; exit 2 means completed analysis meets fail-on; fail-on none does not suppress operational failures. JSON stdout contains only JSON; error paths use stderr without raw trace content. Report version and fingerprint version remain 1. Evidence references identify trace/operation IDs and validated adapter source indices. Schema files were regenerated; global resource/graph checks require ingest/analyze, not structural schemas alone.

## Test quality and security evidence

Baseline: 37 passing tests. Final suite: **69 tests**, adding 32 targeted cases plus stronger assertions in existing CLI tests. The additions focus on failures reproduced during the audit, resource budgets, exact boundary behavior, deterministic capped selection and public/native input validation. No thresholds/assertions were weakened to accept a product defect. Test setup uses a separate bounded compilation budget and runtime-only bundling because WSL declaration compilation from an NTFS mount exceeded the previous 10-second setup hook; declaration validation remains in full builds and consumer typechecking. CLI end-to-end cases have a separate 15-second I/O envelope after measuring WSL cold-start timeouts in cases launching multiple Node processes. Individual CLI subprocesses are also bounded at 15 seconds. Functional assertions and the 50,000-operation detector timing assertion remain unchanged.

The hostile-content subprocess blocks network, DNS, fetch and subprocess APIs, then analyzes URLs, path traversal strings, embedded instructions, tool/name/error/metadata secrets. It returns the expected finding exit code without any attempted external effect or those secrets in default output. Identifier strings deliberately remain visible by contract. JSON prototype keys, unsafe native shapes, nesting/string limits, oversized files, symlink aliases, overwrite/hardlink protection, private POSIX output mode and broken pipes are covered. Heap-budget tests are specific adversarial regression vectors, not a promise that every valid maximum-size input fits a 96 MiB process.

## Remaining limitations and release gates

- **Medium, known privacy limitation:** trace/operation identifiers may themselves contain secrets and are included by the evidence contract. Default reports are not a general anonymizer. Export opaque identifiers and review reports before sharing.
- **Medium, explicit opt-in risk:** show-content can expose arbitrary strings, tool names, IDs and error codes. Key-based redaction catches selected structured keys, not every credential or private value. No guarantee of secret-free opt-in output is made.
- **Low, filesystem assumptions:** parent-component replacement races require trusted directories; existing symlink aliases must be resolved first. Hard-link report publication must be supported. POSIX mode 0600 is checked; Windows uses inherited ACLs. Cleanup is best-effort under OS failures/crashes.
- **Detection limitations:** disjoint windows miss boundary-spanning patterns; incomplete/untimed/concurrent groups can hide genuine problems; exact fingerprints are not semantic equivalence or proof of real-world effects. Leaf-only resource association undercounts some exports. No framework certification or universal OTLP support is claimed.
- **Verification limits:** macOS and hosted runner jobs remain release gates; functional tests are not an exhaustive fuzzing campaign, formal proof, independent penetration test, or Node/OS vulnerability assessment. Dependency audit results are time-dependent.
